- [ ] Auth middleware (проверка JWT-токена) — JWT отсутствует в проекте, пакет `jsonwebtoken` не установлен, auth middleware не реализован
- [ ] Middleware подключён к маршрутам (router.use или per-route) — ни один кастомный middleware не подключён к маршрутам
- [ ] Middleware корректно вызывает next() — кастомных middleware нет
- [ ] Middleware возвращает ошибку при невалидных данных — валидация выполняется inline в контроллерах, а не через middleware
- [ ] Middleware для проверки ролей (если есть) — отсутствует; админские маршруты (`getAllUsers`, `resetUserPassword`, `updateUserRole`) полностью незащищены
- [ ] Middleware для валидации body (если есть) — отсутствует
- [x] CORS настроен (если применимо) — `cors()` подключён в `index.ts`, но с дефолтными настройками (разрешает все origins)

## Что реализовано хорошо

- CORS подключён через пакет `cors` в `index.ts` (строка 23)
- Используются встроенные Express middleware: `express.json()` и `express.urlencoded({ extended: true })`
- В модели `User` реализован Mongoose pre-save hook для хеширования паролей (`models/User.ts`, строки 89-96) — это middleware уровня Mongoose, не Express
- Есть заготовка глобального обработчика ошибок в `index.ts` (строки 38-41)

## Что нужно улучшить

- **Критично: отсутствует auth middleware.** JWT не используется вообще — нет пакета `jsonwebtoken` в зависимостях, нет генерации токенов при логине, нет проверки токенов на защищённых маршрутах. Любой пользователь может выполнить любой запрос, зная ID другого пользователя
- **Критично: нет защиты маршрутов.** Админские эндпоинты (`GET /api/users/all`, `POST /api/users/:id/reset-password`, `PUT /api/users/:id/role`) доступны без авторизации и без проверки ролей
- **Критично: баг в глобальном обработчике ошибок.** В `index.ts` строка 38 параметр объявлен как `_res`, но на строке 40 используется `res` — переменная `res` не определена в этой области видимости, обработчик упадёт с `ReferenceError` при любой ошибке
- **Нет middleware для валидации.** Вся валидация входных данных выполняется внутри контроллеров, что приводит к дублированию кода и нарушению принципа разделения ответственности
- **CORS настроен без ограничений** — `cors()` вызван без параметров, разрешая запросы с любого origin. В продакшене необходимо указать конкретные разрешённые домены
- **Нет выделенной директории `middleware/`** — отсутствует структурная организация для middleware-слоя
- **POST-маршруты для создания данных** (`/api/products`, `/api/blog`, `/api/faq`, `/api/hero`, `/api/catalog`) не защищены — любой анонимный пользователь может модифицировать данные
