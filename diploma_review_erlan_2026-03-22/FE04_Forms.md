# FE04: Формы

## Оценка: 6/10

## Чеклист

- [x] Формы для ввода данных (регистрация, логин, создание/редактирование сущностей)
- [x] Controlled components (value + onChange)
- [ ] Валидация на клиенте (обязательные поля, формат email, длина пароля и т.д.)
- [x] Отображение ошибок валидации
- [x] Обработка submit (preventDefault, отправка данных)
- [x] Очистка формы после успешной отправки
- [ ] Библиотека форм (react-hook-form, formik) — не используется

## Что реализовано хорошо

- Все основные формы (логин, регистрация, CRUD товаров, редактирование профиля) используют controlled components с корректной связкой `value` + `onChange`
- Во всех формах корректно вызывается `e.preventDefault()` и данные отправляются через async thunk или API-вызов
- Форма смены пароля в `AccountPage.tsx` содержит качественную клиентскую валидацию: проверка совпадения паролей, минимальная длина (6 символов), валидация типа и размера файла аватара (до 7MB, только изображения)
- Серверные ошибки отображаются пользователю: в модалке логина/регистрации через `{error && <p className={style.error}>{error}</p>}`, в профиле через отдельные состояния `passwordError` / `passwordSuccess`
- Кнопка submit в модалке блокируется при загрузке (`disabled={loading}`) и показывает текст "Загрузка..." — хороший UX-паттерн
- Формы очищаются после успешной отправки: модалка закрывается и редиректит на `/account`, форма профиля сбрасывает состояние через `setTimeout`, форма товара сбрасывает `formData` при открытии на добавление
- Админ-форма товаров поддерживает как создание, так и редактирование — `formData` корректно заполняется данными существующего товара при редактировании

## Что нужно улучшить

- Клиентская валидация в форме регистрации практически отсутствует — используются только HTML5-атрибуты `required` и `type="email"`, нет проверки длины пароля, формата имени или телефона. Пароль из 1 символа пройдёт валидацию на клиенте
- Поле телефона в регистрации использует `type="number"` вместо правильного паттерна или маски для телефонного номера — это позволяет ввести любое число и не форматирует ввод
- Форма доставки в корзине (`cart.tsx`, строки 283-292) содержит 8 полей ввода (имя, фамилия, город, улица и т.д.), которые полностью декоративные — они не привязаны к состоянию (нет `value`/`onChange`), введённые данные никуда не отправляются и не сохраняются
- В админ-форме товаров нет кастомных сообщений об ошибках валидации — используются только атрибуты `required`, при незаполненных полях показывается стандартный попап браузера
- Нет валидации на уникальность email при регистрации на клиенте (только серверная проверка)
- Форма сброса пароля администратором проверяет длину пароля (минимум 4 символа), но использует `alert()` вместо inline-отображения ошибки, что нарушает консистентность UX
- Не используется библиотека форм (react-hook-form, formik), что при текущем количестве форм привело бы к значительному сокращению бойлерплейта и более надёжной валидации
