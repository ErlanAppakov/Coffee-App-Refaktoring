# FE06: UX-индикаторы

## Оценка: 5/10

## Чеклист

- [x] Индикатор загрузки (loading/spinner) при запросах к API
- [ ] Обработка и отображение ошибок API
- [x] Пустые состояния (empty state) — когда данных нет
- [ ] Уведомления об успешных действиях (toast/notification)
- [x] Disabled кнопки при отправке форм
- [ ] Скелетоны или плейсхолдеры при загрузке

## Что реализовано хорошо

- Текстовые loading-индикаторы присутствуют на большинстве страниц: Hero, CatalogHomePage, DiscountSection, Products, ProductDetail, BlogPage, Faq, AdminPage, а также в поиске (control-panel.tsx) — все показывают текст "Загрузка..." во время ожидания ответа API
- Кнопка "Оплатить заказ" в корзине (cart.tsx) блокируется через `disabled={isProcessing}` при оформлении заказа и меняет текст на "Обработка..."
- Кнопка отправки формы авторизации/регистрации (modal.tsx) блокируется через `disabled={loading}` и меняет текст на "Загрузка..."
- Пустые состояния реализованы в нескольких местах: пустая корзина ("Корзина пуста" + подсказка), отсутствие заказов ("У вас пока нет заказов"), каталог недоступен, товары со скидкой недоступны, FAQ недоступен, "Ничего не найдено" в поиске, "Товары не найдены" и "Пользователи не найдены" в админ-панели
- В userSlice полноценно обрабатываются состояния pending/fulfilled/rejected для loginUser и registerUser с сохранением ошибки в state.error
- Ошибки авторизации отображаются пользователю в модальном окне через `{error && <p className={style.error}>{error}</p>}`
- На странице аккаунта показываются ошибки (`errorMessage`) и успешные действия (`successMessage`) при редактировании профиля и смене пароля

## Что нужно улучшить

- **Нет обработки ошибок API на большинстве страниц.** На страницах Products, ProductDetail, BlogPage, Hero, DiscountSection, CatalogHomePage ошибки API ловятся в catch, но только выводятся в `console.error`/`console.warn` — пользователь не видит никакого сообщения об ошибке. Если бэкенд недоступен, некоторые страницы просто показывают пустоту или текст "Каталог временно недоступен. Запустите backend сервер", что является техническим сообщением, а не пользовательским
- **Нет системы уведомлений (toast/notification).** Успешные действия оповещаются через `alert()` — добавление заказа, удаление товара в админке, смена роли, сброс пароля. Это нативный браузерный `alert`, а не полноценная UI-система уведомлений (react-toastify, notistack и т.п.). В зависимостях нет библиотек уведомлений
- **Нет скелетонов и плейсхолдеров.** Вместо скелетонов используется простой текст "Загрузка..." без какой-либо визуальной стилизации (нет анимированных спиннеров, пульсирующих плейсхолдеров, скелетон-блоков). Единственное исключение — `.loading` класс в admin.module.css, но это тоже просто текст
- **Нет визуального спиннера.** Все loading-индикаторы — это голый текст `<div>Загрузка...</div>` без CSS-анимации или SVG-спиннера. Нет компонента Spinner/Loader для переиспользования
- **Отсутствует обратная связь при добавлении товара в корзину.** При нажатии "В корзину" на карточке товара нет никакого визуального подтверждения — ни toast, ни анимации, ни изменения состояния кнопки. Пользователь может не заметить, что товар добавлен
- **В AdminPage нет блокировки кнопок во время асинхронных операций** (сохранение/удаление товара, сброс пароля, изменение роли) — повторные нажатия могут вызвать дублирование запросов
