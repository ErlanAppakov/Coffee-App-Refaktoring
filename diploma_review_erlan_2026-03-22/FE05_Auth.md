## Что реализовано хорошо

- Формы логина и регистрации реализованы в модальном окне (`modal.tsx`) с переключением между режимами через `toggleModalType`. Формы имеют валидацию (`required`, обработку ошибок), индикатор загрузки (`loading`), отображение серверных ошибок.
- `PrivateRoute` (`privateRoute.tsx`) защищает маршрут `/account` — проверяет `isAuth` из Redux и дублирует проверку через `localStorage`, восстанавливает сессию при перезагрузке страницы.
- `AdminRoute` (`AdminRoute.tsx`) проверяет `role === "admin"` и редиректит не-админов на `/account`, неавторизованных — на `/`.
- Logout в `AccountPage.tsx` корректно очищает Redux-состояние (`logout()`), корзину (`clearCart()`), удаляет `currentUser` из `localStorage` и перенаправляет на главную.
- Восстановление сессии из `localStorage` при загрузке приложения реализовано в `App.tsx`, `PrivateRoute` и `AdminRoute`.
- В модели User на бэкенде есть роли `user`/`admin`, и на фронтенде AdminRoute их проверяет.

## Что нужно улучшить

- **JWT-токены не используются.** Бэкенд (`userController.ts`) при логине и регистрации возвращает просто объект пользователя без токена. В `localStorage` сохраняется весь объект пользователя, а не токен. Это не является полноценной авторизацией — любой может вручную создать запись в `localStorage` и получить доступ.
- **Authorization-заголовок не отправляется.** В `api.ts` функция `fetchAPI` не добавляет заголовок `Authorization: Bearer <token>`. Все API-запросы идут без аутентификации. Это означает, что бэкенд-эндпоинты (включая админские: `getAllUsers`, `resetUserPassword`, `updateUserRole`) доступны любому без проверки прав.
- **Бэкенд-маршруты не защищены middleware.** В `userRoutes.ts` нет auth-middleware — все эндпоинты публичны. Это критическая уязвимость безопасности.
- **Роли проверяются только на фронтенде.** `AdminRoute` проверяет `role === "admin"` из `localStorage`, но бэкенд не валидирует роль при выполнении админских операций. Любой может вызвать API напрямую.
- **Нет refresh token.** Механизм обновления токена отсутствует, как и сами JWT-токены.
- **setTimeout для проверки сессии.** В `PrivateRoute` и `AdminRoute` используется `setTimeout(() => setIsChecking(false), 100)` — это ненадёжный подход; следует дождаться фактического обновления Redux-состояния.
- **Дублирование логики восстановления сессии.** Один и тот же код восстановления из `localStorage` дублируется в `App.tsx`, `PrivateRoute` и `AdminRoute`.
