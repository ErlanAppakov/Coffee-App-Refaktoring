# BE06: Структура Backend

## Оценка: 7/10

## Чеклист

- [x] Разделение на routes/, controllers/, models/
- [x] Роутер в отдельных файлах (не всё в index.ts)
- [x] Контроллеры отделены от маршрутов
- [x] Модели в отдельной папке
- [x] Конфигурация БД вынесена (config/)
- [ ] Middleware в отдельной папке/файле
- [x] .env / .env.example для секретов
- [x] package.json с зависимостями

## Что реализовано хорошо

- Чёткое разделение на слои: `routes/`, `controllers/`, `models/`, `config/` — каждая сущность (User, Product, Blog, FAQ, Hero, Catalog) имеет свой файл в каждом слое
- Роуты чистые и лаконичные — содержат только маппинг HTTP-метод/путь на контроллер, без бизнес-логики
- Контроллеры полностью отделены от маршрутов, каждый контроллер работает только со своей моделью
- Модели хорошо типизированы с TypeScript-интерфейсами (IUser, IProduct, IBlog и т.д.), используют Mongoose Schema с валидацией и enum
- Конфигурация подключения к БД вынесена в `config/database.ts` с обработкой ошибок и таймаутами
- Есть `.env.example` и `.gitignore` с исключением `.env` — секреты не попадают в репозиторий
- Точка входа `index.ts` минимальна: только подключение middleware, монтирование роутов и запуск сервера
- Есть служебные скрипты (`scripts/importData.ts`, `scripts/updatePassword.ts`) для утилитарных задач
- Строгий `tsconfig.json` с `noUnusedLocals`, `noImplicitReturns` и другими проверками

## Что нужно улучшить

- Отсутствует папка `middleware/` — глобальный обработчик ошибок определён инлайн в `index.ts` (строки 38-41), а auth-middleware (проверка JWT-токена) полностью отсутствует, хотя есть эндпоинты, требующие авторизации
- Нет слоя `services/` — бизнес-логика (создание заказа, расчёт скидки, хеширование пароля) находится непосредственно в контроллерах, что затрудняет повторное использование и тестирование
- Нет слоя `validators/` — валидация входных данных разбросана по контроллерам вместо централизованных middleware (например, Joi или Zod)
- Дублирование маппинга User-объекта в ответ: формирование `{ id, name, email, phone, avatar, role, discount, orders }` повторяется в `register`, `login`, `getUser`, `getAllUsers`, `updateUserRole` — стоит вынести в общий метод `toJSON` или DTO
- В `importData.ts` дублируется логика подключения к БД вместо переиспользования `config/database.ts`
- Ошибка в глобальном обработчике ошибок `index.ts:40`: используется `res` вместо `_res` — переменная переименована, но обращение не обновлено
