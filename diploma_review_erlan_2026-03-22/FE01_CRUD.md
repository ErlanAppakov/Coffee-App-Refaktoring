# FE01: CRUD через UI

## Оценка: 7/10

## Чеклист

- [x] Создание сущности через форму (Create)
- [x] Отображение списка сущностей (Read - List)
- [x] Отображение детальной страницы (Read - Detail)
- [x] Редактирование сущности (Update)
- [x] Удаление сущности (Delete)
- [x] Обновление UI после мутаций (создание/обновление/удаление)
- [x] Подтверждение перед удалением

## Что реализовано хорошо

- Полный CRUD для товаров (Products) реализован в админ-панели (`AdminPage.tsx`): создание через форму с полями (название, описание, изображение, рейтинг, цены по весам, скидка), редактирование через ту же форму с предзаполнением данных, удаление с `window.confirm`
- UI обновляется после каждой мутации — вызывается `fetchProducts()` после создания, редактирования и удаления товара, что обеспечивает актуальность данных
- Корзина реализована полноценно через Redux (`cartSlice.ts`): добавление товаров, изменение количества (инкремент/декремент), удаление отдельных товаров, очистка всей корзины с подтверждением через `window.confirm`
- Отображение списков товаров по категориям и подкатегориям (`products.tsx`) с пагинацией «Показать еще»
- Детальная страница товара (`productDetail.tsx`) с выбором веса, количества и кнопкой «Купить»
- Создание заказов через корзину с сохранением на сервере (`usersAPI.createOrder`), удаление истории заказов с подтверждением
- Управление пользователями в админке: просмотр списка, изменение роли, сброс пароля

## Что нужно улучшить

- CRUD для товаров доступен только в админ-панели — обычный пользователь не может создавать/редактировать/удалять собственные сущности (например, отзывы, адреса доставки, профильные данные помимо аватара и пароля)
- Для товаров используется единый эндпоинт `productsAPI.updateAll`, который перезаписывает весь массив данных целиком при каждой операции (создание/редактирование/удаление одного товара) — это неэффективно и рискованно при конкурентных запросах
- Отсутствуют отдельные REST-эндпоинты для CRUD-операций над отдельным товаром (POST /products, PUT /products/:id, DELETE /products/:id) — вместо этого все операции идут через один POST /products с полной заменой данных
- Нет возможности редактирования или удаления отдельного заказа — можно только удалить всю историю целиком
- Удаление товаров из корзины происходит без подтверждения (только «Удалить все» имеет `window.confirm`), удаление отдельного товара не запрашивает подтверждение
- Генерация 40 «фейковых» товаров прямо во фронтенде (`generateProducts`) для заполнения каталога — это не настоящие данные, и функция дублируется в двух файлах (`products.tsx` и `productDetail.tsx`)
